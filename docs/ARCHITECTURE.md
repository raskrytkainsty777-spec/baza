# Комментарии в лиды — архитектура

> Обновлено: 2026-09-03. Расчёты — на выборке 1484 поста · 75 источников · 45 дней · Москва.

Сервис сам находит риелторов по городам, следит за их продающими постами
и вытаскивает из комментариев людей с реальным интересом — уже с номером телефона.

---

## 1. Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Сервер | Новый: `95.81.103.196`, 4 CPU / 7.7 ГБ / 80 ГБ, Amsterdam | Старый (1 CPU / 1.8 ГБ, swap 84%) не тянет. Новый в той же сети — 0.36 мс до старого |
| Пробив номеров | Остаётся на старом `132.243.114.17` | Telegram-сессии привязаны к IP, переезд рискует потерей входа |
| БД | PostgreSQL 16 | 5 городов → ~20k комментариев/сутки, 7–8 млн строк/год; SQLite пишет в один поток |
| Бэкенд | Python 3.12 · FastAPI · SQLAlchemy 2 async · asyncpg · Alembic | Рабочий клиент parser.im, дедуп и фильтры уже написаны и проверены; пакетная обработка текста и bulk-вставки |
| Фронт | React 18 · TypeScript · Vite · Mantine 7 · TanStack Query 5 | Готовый UI-кит для админки, таблицы/фильтры/графики из коробки; совпадает с другим сервисом заказчика |
| Очередь | В PostgreSQL (`FOR UPDATE SKIP LOCKED`) | Один сервер, одна служба. Redis и Celery не нужны |
| Деплой | git pull + `alembic upgrade` + `vite build` + `systemctl restart` | Без Docker и Coolify: меньше слоёв на машине, которую администрируем по SSH |
| Кодовая база | Отдельный сервис и репозиторий | Изоляция от боевых систем, независимый деплой |

Две службы systemd: `baza-api` (uvicorn) и `baza-worker` (планировщик). nginx отдаёт статику фронта и проксирует `/api` на uvicorn.

## 2. Конвейер

Две петли. **Разовая** — при заводе донора. **Ежедневная** — на мониторе.

```
 РАЗОВО
 01 поиск            задачи: теги / ключи (p3/p5 act=5) · рекомендации (Apify relatedProfiles, сиды выбирает
                     оператор галочками в «Донорах»). Несколько задач параллельно, у каждой свои этапы
 02 фильтр f1        по контактам задачи: активен ≤30 дн, подписчики, био → имя, описание, адрес
 03 ИИ: кто и где    по имени + описанию + адресу: (а) вид деятельности — риелтор / застройщик / агентство берём,
                     ипотечный брокер / стройка / ремонт отсеиваем (критерии — в промпте, Настройки);
                     (б) город и уверенность
 04 распределить     кнопка: в город уходят только 100%-уверенные, статус «новый».
                     Неразобранные (город неясен, два города) — отдельная ветка: донор «неразобранный»,
                     посты собираем так же, а ИИ по каждому продающему посту определяет ГОРОД → пост (источник)
                     уезжает в свой город. Донор при этом города не имеет
 05 новый донор      p1 act=6 — все посты за intake_days (настройка, по умолчанию 45); ИИ размечает каждый:
                     продающий? оффер, крючок, категория, призыв, код; для неразобранных — ещё и город
 06 первый сбор      p2 act=3 (web=1, без dop и без фильтров по автору) — комментарии со всех продающих постов,
                     отсев по дате комментария (≤ comment_fresh_days) и ответов самого донора — у себя
 07 на монитор       донор становится «старым»

 ЕЖЕДНЕВНО, по расписанию из настроек
 08 новые посты      Apify по донорам на мониторе; новый пост → ИИ-разметка
 09 прирост          Apify сверяет счётчики всех известных постов: вчера → сегодня
 10 досбор           обычные посты — p2 act=3 (web=1) целиком, дедуп по id комментария;
                     крупные (≥ big_post_threshold комментариев) — Apify comment-scraper с лимитом:
                     отдаёт свежие первыми, за секунды и копейки, без перекачки всего поста
 11 квалификация     ИИ: комментарий + текст поста → лид / мусор + суть
 12 отсек города     лиды копятся как «непробитые»; проверка базы: номер есть → ставим, на пробив не шлём
 13 пробив           вручную (по датам актуальности) или авто. На сервис пробива уходит ВСЯ строка: search=instagram.com/login,
                     lead_id, город, комментарий, дата, url поста, разбор поста. Постбек: lead_id + номер → база
 14 в CRM            пробитые уходят хуком на 3-й сервис с lead_id (шлёт этот сервис, не пробив). Постбек: статус по lead_id
 15 дашборд          динамика по дням, конверсии, стоимость — по городу, донору, крючку, категории
```

**Разделение инструментов.** parser.im (10 одновременных строк: логинов / тегов / ссылок, сверх — очередь):
поиск, фильтр, посты нового донора, все комментарии. Apify: только новые посты и счётчики, ежедневно.
**Никакого `dop` и никаких фильтров по автору в заданиях сбора** — это фильтрация во время парсинга, она
роняет скорость в сто раз (3.6 → 318 комм/мин). Телефоны только через пробив: в профилях инстаграма
могут быть номера администраторов. Сбор комментариев — `web=1`.
Приоритет строк parser.im, пока их 10: досбор по приросту → посты новых доноров → f1 → поиск.
Встроенной фильтрацией parser.im не пользуемся — медленная. Мониторинг `m1` не используем — держит слоты.

**Экраны** (списки, не провалы): Мастер задач · Поиск доноров (карточки задач с этапами) · Доноры
(все города, фильтр, сортировка, галочки для сидов) · Посты (все города, новые за день, прирост) ·
Город (комментаторы за период, отсеки непробитых/пробитых, пробив, связки: токен задачи пробива,
постбек, CRM, статусы, цены, правила) · Задания · Журнал · Настройки (ключи, расписание, бот, промпты).
Экрана комментаторов нет — это статистика; ИИ сегментирует.

## 3. Модель данных

### `lg_cities` — города, они же проекты
```
id · name · is_active
cost_per_contact                 цена запроса пробива
cost_per_handling                цена обработки одного контакта
comment_fresh_days               брать комментарии не старше N дней
donor_min_median                 порог медианы комментов на пост для донора (по умолчанию 30)
post_freeze_days                 пост без прироста N дней снимается с обхода (30)
resend_after_days                повторно отдать того же человека не раньше чем через N дней
probe_mode                       manual | auto
probe_hook_token                 токен задачи на сервисе пробива
crm_webhook_url · crm_secret     куда слать лиды этого города
send_mode                        auto | manual
apify_daily_cap_usd              потолок расходов Apify в сутки
```

### `lg_settings` — общие настройки (ключ → значение)
```
intake_days                      окно постов при заводе донора (45)
comment_fresh_days_default       окно свежести комментариев по умолчанию
parserim_lines                   строк в тарифе (10)
big_post_threshold               с какого числа комментариев пост считается крупным и досбирается через Apify (1000)
schedule.*                       расписание кронов
prompt.post · prompt.comment · prompt.city · prompt.activity   промпты ИИ, редактируются в UI
```

### `lg_search_tasks` — задачи поиска доноров (глобально, не по городам)
```
id · kind                        hashtag | keyword | recommendation
input                            теги / ключи / список сидов
stage                            collecting → filtering → classifying → ready → distributed
collected · passed · rejected_inactive · rejected_activity · confident · unclear
created_at · stage_changed_at
```
Город кандидата — результат f1 + ИИ, а не вход поиска. Кандидаты (`lg_candidates`: task_id, username,
f1-данные, city_id, confidence) живут внутри задачи до распределения.

### `ig_accounts` — все инстаграм-аккаунты, что мы видели (и доноры, и комментаторы)
```
id · username (unique) · ig_id
full_name · bio · followers · following · posts_count · last_post_at · is_private · is_business
roles                            donor / commenter / both
city_id · city_source            ai | f1 | manual
phone · phone_source             probe | manual — только через пробив, из инстаграма номера не берём
probe_status · probed_at · probe_raw
first_seen_at · updated_at
```
Единый справочник. Если `phone` заполнен — пробив не повторяется, берём готовый.

### `lg_donors` — донор в городе (один аккаунт может работать по нескольким)
```
id · account_id · city_id
status                           new / monitored / paused / unclassified
                                 unclassified — город донора неясен; его продающие посты получают город от ИИ
intake_stage                     для new: posts → ai → comments → done
found_via · search_task_id       hashtag | keyword | recommendation | manual
added_at · status_changed_at · status_reason
```
«Топа» нет: сортировка по лидам, комментам, стоимости лида (когда придут статусы).

### `lg_posts` — посты и рилсы доноров
```
id · shortcode (unique) · donor_id · city_id · city_source      donor | ai (для неразобранных доноров)
url · caption · published_at · product_type      feed | clips | carousel
views · likes
comments_count · comments_count_prev · comments_delta · last_growth_at · last_checked_at
offer · hook · category · cta_type · code_word · is_selling · ai_at
monitor_status · zero_growth_days                active / frozen
```

### `lg_comments` — сырые комментарии, лог и защита от повторов
```
id · ig_comment_id (unique) · post_id · city_id
author_account_id · author_username
text · written_at · collected_at · job_id
is_donor_reply                   комментарий самого донора — в квалификацию не идёт
qualification                    pending / lead / ignore / prefiltered
ai_reason · ai_summary
age_distance_days                разрыв между выходом поста и комментарием
```
Текст у `ignore` чистится через 30 дней, id остаётся для дедупликации.

### `lg_leads` — то, что ушло в работу
```
id · comment_id · post_id · account_id · city_id
phone · phone_from               probe | base | f1
probe_status · probed_at
sent_at · outbound_status
crm_status · crm_updated_at      new / negative / application / qual / deal
cost_contact · cost_handling     снимок цен на момент создания
created_at
```

### `lg_jobs` — задания parser.im и прогоны Apify
```
id · provider                    parserim | apify
tid / run_id · type · act · purpose · city_id · payload
state · count · rows_imported · error
created_at · started_at · finished_at
```

### `lg_inbox` — прокладка на приёме
```
id · event_id (unique) · source · raw_body · received_at
state · attempts · error         pending / done / error
```
Эндпоинт делает ровно одно: записал и ответил 200. Разбор — воркером.

### `lg_outbox` — прокладка на отправке
```
id · lead_id · payload · created_at
state · attempts · next_try_at · last_code · last_error
```
Лид и запись в outbox — одна транзакция.

### `lg_rejects` — кого смотрели и не взяли
```
username (unique) · reason · city_id · checked_at
```

### `lg_events` — журнал действий системы
```
id · at · kind · entity · entity_id · message · payload
```
«Донор X → архив: медиана 4 < 30». Чтобы автоправила были объяснимы.

### `lg_stats_daily` — витрина дашборда
```
date · city_id · hook · category
comments · leads · probed · sent · applications · quals · deals · spend_contact · spend_handling
```
Пересчёт ночью и по запросу.

## 4. Воркеры (`backend/app/workers/`)

| Воркер | Ритм | Что делает |
|---|---|---|
| `discovery` | по задаче | Ведёт задачу поиска по этапам: сбор → f1 → ИИ-город → готово к распределению |
| `donor_intake` | по событию | `p1` за 45 дней → ИИ-разметка → первый сбор `p2` по продающим → донор на монитор |
| `posts_sync` | 1–2 раза в день | Apify: новые посты + счётчики по горячей базе, расчёт прироста |
| `comments` | раз в день | `p2` по постам с приростом, импорт, дедуп по `ig_comment_id` |
| `ai_posts` | по очереди | Оффер, крючок, категория, тип призыва, кодовое слово |
| `ai_comments` | по очереди | Квалификация комментария в связке с текстом поста |
| `probe_feeder` | непрерывно | Проверка базы → отправка на старый сервер → приём номера |
| `outbox_worker` | непрерывно | Отправка лидов в CRM, повтор с растущей паузой |
| `inbox_worker` | непрерывно | Разбор статусов из CRM |
| `job_runner` | непрерывно | Очередь заданий parser.im: режет по 10 строк, приоритет комментарии → фильтр → поиск, забор результатов, ретраи |
| `rollup` | ночью | Витрина, рейтинги доноров, автоправила, чистка текста мусорных комментариев |
| `alerts` | по событию | Telegram-уведомления о сбоях и порогах |

## 5. Кто что собирает

### parser.im
| Задание | Зачем | Ключевое |
|---|---|---|
| `p3 act=5` | Авторы постов по хэштегам | Без фильтров, только список |
| `p5 act=5` | Авторы постов по ключевым словам | Ловит тех, кто тегов не ставит |
| `f1` | Отбор и догрузка данных | Источник — id предыдущего задания. `lastpost`, `followers1/2`, `white_bio`, `white_address`. Отдаёт телефон, email, имя, город, описание |
| `p1 act=6` | Все посты нового донора за 45 дней (разово) | `spec=1,2,4,5,6,7`, `limit2` на аккаунт; окно по дате режем у себя |
| `p2 act=3` | Комментарии по ссылкам на посты | `spec=1,2,3,4,6`, `web=1`; много постов в одном задании; **без `dop` и без фильтров** — 318 комм/мин против 3.6 |

### Apify
| Операция | Ритм | Актор / параметр |
|---|---|---|
| Новые посты доноров | 1–2 раза в день | `apify/instagram-scraper`, `onlyPostsNewerThan: "1 day"` |
| Счётчики по горячей базе | раз в день | `apify/instagram-post-scraper`, список URL, одна строка на пост с `commentsCount` |
| Рекомендации | по задаче | `relatedProfiles` от сидов, которых оператор отметил галочками в «Донорах» |
| Досбор на крупных постах | раз в день | `apify/instagram-comment-scraper`, `resultsLimit` ≈ вчерашний прирост × 2. Проверено: порядок **новые → старые**, 15 строк за 6 с |

Смета на московскую базу: ~$2/день Apify (651 горячий пост + ~33 новых). Тиры по возрасту поста режут вдвое.

## 6. Экраны

- **Дашборд** — города строками, метрики столбцами, период день/неделя/месяц. Поток, конверсии, стоимости, срез по крючкам и категориям, очередь непробитых.
- **Город → Доноры → Посты → Лиды** — четыре уровня. Город: доноры, поиск через рекомендации, пороги, цены, теги/ключи. Донор: посты, рейтинг, история, пауза. Пост: текст, разбор ИИ, график прироста. Лиды: кто, что, под чем, номер, статус.
- **Задания** — очередь parser.im/Apify: что в работе, что упало, слоты.
- **Журнал** — `lg_events`.
- **Настройки** — ключи, лимиты, Telegram для оповещений.

## 7. Контракты

### Наружу — готовый лид (POST на URL из настроек, заголовок `X-Hook-Secret`)
```json
{
  "lead_id": 84512,
  "city": "Москва",
  "username": "ivan_petrov",
  "profile_url": "https://instagram.com/ivan_petrov",
  "phone": "+79161234567",
  "phone_from": "base",
  "comment": "5",
  "written_at": "2026-09-03T11:04:00Z",
  "post": {
    "url": "https://instagram.com/p/DbCqUc6N3h2/",
    "offer": "таунхаус от 16 млн, Москва",
    "hook": "низкий ежемесячный платёж",
    "category": "таунхаус",
    "cta": "коммент, кодослово",
    "age_distance_days": 12
  }
}
```

### Внутрь — статус из обработки
```
POST /api/leadgen/status
X-Hook-Secret: …
{ "lead_id": 84512, "status": "qual", "comment": "готов смотреть в выходные", "at": "2026-09-04T09:20:00Z" }
```
Статусы: `negative` · `application` · `qual` · `deal`. Привязка строго по `lead_id`.

### Пробив — старый сервер
Используется существующий приём по вебхуку: `POST /api/hook/{token}` с `{query, ref, payload}`,
ответ приходит на `callback_url` с разобранным телефоном. Сценарий на старом сервере — `instagram`.

## 8. Автоправила

- Пост без прироста `post_freeze_days` → `frozen`. Возвращается, если счётчик дёрнется при недельной сверке.
- Донор с медианой ниже `donor_min_median` → `archived` (с записью причины в `lg_events`).
- Донор без постов 30 дней → `paused`.
- Комментатор с номером в базе → пробив не повторяется.
- Повторная отдача того же человека — не раньше `resend_after_days`.
- Комментарии самого донора (`is_donor_reply`) — в квалификацию не идут.
- Доля новых в обходе рекомендаций < 10% → граф города выбран.
- Расход Apify за сутки ≥ `apify_daily_cap_usd` → прогоны стоп + оповещение.

## 9. Метрики

```
затраты = пробитых × cost_per_contact + обработанных × cost_per_handling
CPL     = затраты / заявки
CPQ     = затраты / квалы
CPO     = затраты / сделки
```
Цены — снимком в лид на момент создания. Разрезы: город · крючок · категория · донор.

## 10. Порядок работ

| Фаза | Что | Чем заканчивается |
|---|---|---|
| 0 · разведка | `p1` и `p2` по 10 донорам через API: формат колонок, скорость, слоты, доля телефонов в `dop` | Понятно, сколько заданий в сутки и укладываемся ли в слоты |
| 1 · фундамент | Сервер, PostgreSQL, миграции, каркас API и фронта, деплой, импорт xlsx | 1484 поста и 75 источников в базе, дашборд показывает их |
| 2 · разбор и лиды | ИИ на постах и комментариях, пробив с проверкой базы, outbox в CRM | Первые лиды с номерами на уже собранных данных |
| 3 · суточный цикл | Apify: посты и счётчики; `p2` по приросту; автоправила | Москва работает без ручных запусков |
| 4 · дашборд | Inbox статусов, витрина, экраны аналитики | Видна стоимость сделки по городу и офферу |
| 5 · рост | Теги/ключи → `f1` → карантин; рекомендации; второй город | База доноров растёт сама |

Фаза 2 раньше парсинга специально: на 186 тыс. уже собранных комментариев можно увидеть реальную конверсию, не потратив ни доллара.
