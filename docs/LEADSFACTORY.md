# Leads Factory — закупка номеров через Open API

Спецификация: `https://openapi.leads-factory.ru/v1/openapi.json` (Swagger: `/v1/docs`). База знаний с картинками
экранов: `lf-school.ru/training` (нужен вход). Один Bearer-токен на аккаунт, выдаётся в их ЛК: Open API → Выдать
токен. У нас хранится в Настройках («Leads Factory — токен Open API»), хелпер на сервере:

```bash
/opt/baza/lf.sh GET /v1/vdl/api/projects/get_all "page=1&limit=50"
/opt/baza/lf.sh PUT /v1/vdl/api/sources/add_all/28469 "" '{"source":["79990000000"],"source_type":"phone","source_from":"web","label":"18.03","label_color":"sky","geo_ids":[]}'
```

Тестовый проект: **«невские звезды», crm_id 28469**.

## Модель

- **Проект** (`crm_id`) — клиент. Создаётся в основном ЛК (`crm POST /projects`) или менеджером LF.
- **Источник** — номер телефона или домен, с которого закупаем. `sources/add_all`; подпись `label` только вместе
  с `label_color` из `sources/available_colors`; вкл/выкл — `will_work` (`update_will_work_bulk`).
- **Тег** — источник × тип поставщика, заводится системой сам. Код `Bxyz`:
  первая цифра — оператор: **1 Мегафон (зелёный), 2 Билайн (жёлтый), 3 МТС (красный)**;
  последняя — что парсим: **1 исход по доменам (сайты), 2 исходящие звонки с номера-источника,
  3 входящие звонки на номер-источник**.
  В справочнике `tags/available_tags_types` только B111, B221, B222, B223, B333. Для телефонов система создаёт
  B111, B222, B223, B333. Для закупки по номерам нужны 222, 223, 333; B111 выключаем.
- **Норма** тега (`norm_work`) — наше решение «закупать»; **«Включён»** (`status`) — фактический статус, его ставит
  их планировщик после 20:00 МСК. Ручное переключение `norm_work` выкл→вкл через API даёт «Включён» на минуту,
  потом планировщик откатывает — не полагаться.
- **Лимит** — на тег в сутки. Массово дельтой `tags/increment_limits`; базовый для новых — `projects/info default_limit`;
  автоповышение — `projects_settings/update_auto_scripts_settings limit_autochange`. Лимита на проект в день нет.

## Деньги

- «Баланс в контактах» = поступление в ₽ / `answer_cost`. Цена и порог остановки — `crm payment/update`
  (`answer_cost`, `min_client_balance`); остаток и история — `crm finance/get` (`client_balance` по дням, `recoupments`).
- **Поступление через API не вносится** — только руками в ЛК: Проект → Финансы → Поступление.
- Старт/стоп закупки — `crm PATCH /projects/{id}` поле `status` (`active`, из FAQ также `stop`, `pause`).

## Номера

- Купленные — «Заявки» проекта в ЛК; через API `crm GET /projects/{id}/answers` (телефон, оператор, регион, дата, статус).
- Вебхука в API нет. «Опишка» — исходящий webhook LF на URL партнёра — настраивается в ЛК: Проект → Интеграции → API.
- Дубли за «дни без повтора» помечаются «Повтор» и по интеграциям не уходят.

## Правила

- Изменения настроек применяются циклом **до 20:00 МСК**, иначе на сутки позже.
- Не грузить домены и телефоны одной партией — тип распознаётся неверно.
- Чёрный список проекта: сайт и номера самого клиента, чтобы не закупать у него же.
