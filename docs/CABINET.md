## 0. Роли

| Роль | Вход | Что видит |
|---|---|---|
| Админ (мы) | baza, токен | вкладка ГЦК: клиенты, их баланс, всё содержимое любого кабинета |
| Клиент | `/cabinet`, логин + пароль | свои проекты, компании, база, досбор, интеграции, настройки |
| Агент досбора | `/agent`, логин + пароль | свои задачи, ресурсы, добавление источников, баланс, реквизиты |

## 1. Админ: вкладка ГЦК

- Кнопка «Создать проект»: логин, пароль → клиент в нашей базе. Тут же создаётся проект в LF
  (`crm POST /projects`, тип VDL) и проставляются наши стандартные настройки: цена заявки, мин. остаток 0,
  базовый/максимальный лимит, автоповышение выкл, статус закупки.
- **Начисление баланса через API LF невозможно** (проверено: поступление только руками в их ЛК). Процесс:
  создали клиента → вручную внесли поступление в LF → сервис сам подтягивает `finance/get` и показывает
  доступный баланс. Обновление раз в N секунд (предложение: 60).
- Баланс показываем **в контактах**: остаток ₽ / цена заявки. 5 000 ₽ при 5 ₽ = 1 000 контактов.
- Список клиентов: логин, проект LF, баланс в контактах и ₽, куплено сегодня / всего, статус закупки, вход в кабинет
  «от имени клиента».

## 2. Кабинет клиента

### 2.1 Мои проекты
- «Добавить проект» → загрузка источников: по одному номеру в строке; либо `номер;компания` (разделитель выбирается).
  Компания — откуда взят номер; повторяется у многих источников.
- Выбор поставщиков (сейчас: Билайн исходящие B222, Билайн входящие B223, МТС входящие B333; остальные позже).
- Лимит на **связку** номер × поставщик: ввели 5 → у каждого поставщика по 5.
- «Добавить источники» → уходят в LF (`sources/add_all` с меткой = компания), теги ненужных поставщиков выключаются,
  лимиты выставляются.
- Таблица источников, сортировка по каждому столбцу: чекбокс · ID (LF) · номер · компания · дата добавления ·
  статус (включён/выключен) · контактов всего · контактов сегодня · **[предложение]** лимит, включённые поставщики,
  последний контакт, повторов, себес/успешки LF за 14/28 дн.
- Поиск по номеру и по названию компании. Пагинация 20/50/100/все, по умолчанию 20. Массовый чекбокс — текущая страница.
- Массовые действия: лимит (число → всем выбранным); регионы — добавить/исключить (в LF есть: `source_geo` — 83 региона,
  `sources/update_settings geo_ids`); включить/выключить; **дни недели** (в LF нет — наша логика, см. 2.6).

### 2.2 Чёрный список
Номера, которые не закупаем → LF `crm POST /projects/{id}/blacklist/add`. Вставили — ушло в проект.

### 2.3 Компании
По каждой компании: источников · куплено номеров · лидов · неуспешных · квал-лидов · конверсия ·
стоимость лида · стоимость квал-лида.
Стоимость = (номеров × цена покупки контакта + номеров × цена обработки контакта) / лидов (или квал-лидов).
Цены покупки и обработки — в настройках проекта клиента.

### 2.4 Статусы по вебхукам
Три входящих вебхука клиента: **неуспешный · лид · квал-лид**. Прокладка `inbox`, ничего не теряет.
Сторонний сервис шлёт статус + номер → ищем номер в базе проекта → источник → компания → плюс в статистику компании.

### 2.5 База
Все контакты проекта из LF (`crm answers`), опрос по интервалу — LF сам не пушит. Столбцы: оператор · источник ·
контакт · дата (порядок даст заказчик). Дублей не чистим: разные поставщики дают одинаковые номера — база = копия LF.

### 2.6 Расписание по дням недели (наша логика)
Чекбоксы пн–вс. Если день не отмечен — накануне до 20:00 МСК выключаем все включённые источники; если следующий
отмечен — накануне включаем обратно те, что выключило расписание. Источники, выключенные руками за
неэффективность, расписание не трогает (два разных флага: «выключен оператором» и «выключен расписанием»).

### 2.7 Настройки клиента
- Цена покупки контакта, цена обработки контакта (для 2.3).
- Интеграции (раздел 4). Telegram-бот (раздел 5).

## 3. Досбор (агенты собирают новые источники)

- «Добавить агента»: логин, пароль, имя → доступен при настройке задач.
- «Добавить ресурсы»: модалка, многострочное поле `сайт;компания`, название списка; считаем сайты.
- «Создать задачу»: список ресурсов · агенты, кому доступна · цена за один уникальный источник · лимит уникальных
  источников на задачу (не на агента) · чекбокс «новые источники сразу в закупку» + лимит на связку для них.
- Редактирование задачи: поднять лимит, добавить ресурсы. Выключенная задача у агентов не видна.
- Статистика задачи: по датам, какой агент сколько уникальных добавил; выгрузка CSV или только номера;
  все новые источники можно отправить в закупку.

### Кабинет агента
- Вверху: имя, баланс (начисления за уникальные источники), список активных задач.
- «Получить ресурсы»: нумерованный список сайтов, клик — сайт в новой вкладке. «Назад».
- «Добавить источник»: компания — только из списка компаний задачи (поиск + выпадающий список, свободный ввод
  запрещён) → номер с маской +7 → проверка на дубль внутри проекта → подтверждение → добавить → баланс агента +цена.
  Лимит задачи исчерпан — добавить нельзя.
- Реквизиты: иконка кошелька, СБП или карта, банк, реквизиты. Без реквизитов первый источник не добавить.
- Выплата: у нас по агенту «Обнулить баланс» — видим реквизиты и сумму, платим руками, баланс агента обнуляется.
- Если у задачи включено «сразу в закупку»: уникальный источник сразу уходит в LF на всех включённых поставщиков
  с меткой = компания и лимитом из задачи.

## 4. Интеграции клиента (выгрузка контактов)

Общее: статус «подключена / не подключена», проверить, изменить, удалить, «отправить тестовый лид»
(79999999999, источник «тест», текущая дата).
- **Google Sheets**: сервисный аккаунт (JSON даёт заказчик, в .env); клиент даёт таблице доступ редактора на этот
  аккаунт, вставляет URL, «Проверить», выбирает соответствие столбцов, сохраняет. Новые контакты дописываются строками.
- **Bitrix24**: входящий вебхук клиента; онбординг с подсказкой прав (crm, user); лиды или сделки; создавать контакт
  или нет (если да — проверка дублей); подтягиваем ответственных, воронки и стадии; выбор ответственного, воронки,
  стадии (лиды — первый этап по умолчанию); поля: заголовок, телефон (тип рабочий/мобильный — подсказать), источник —
  в комментарий или заголовок, по желанию.
- **AmoCRM**: токен + поддомен, помощь в настройке.
- **Внешний коннектор**: GET или POST на URL клиента. Да, это и есть отправка по API — то же, что вебхук наружу.

## 5. Telegram-бот
Токен бота — в .env и в настройках ГЦК (вставляет админ). Клиент в своём кабинете нажимает «Подключить бота»,
делает /start — чат запоминается. Уведомления в 19:00 МСК: куплено контактов за день; остаток на балансе в
контактах; на сколько дней хватит при среднем расходе.

## Этап 3 — интеграции (сделано 05.09)

- ГЦК → блок Google: название аккаунта (как подписываем клиенту), JSON ключ сервисного аккаунта, «Проверить ключ»
  (разбираем JSON, просим у Google токен — ничего не сохраняя), «Сохранить» → `lg_settings.google_sa_json` / `google_sa_name`.
  Один аккаунт на всех клиентов. Запасной путь — файл из `.env GOOGLE_SA_JSON`.
- Кабинет клиента → вкладка «Интеграции»:
  - Google Таблицы: клиент даёт таблице доступ редактора на почту аккаунта, вставляет ссылку, «Проверить»
    (название, листы, первая строка), выбирает лист и порядок столбцов (оператор, источник, контакт, дата, поставщик,
    компания, регион, статус LF), заголовки пишем в пустую первую строку. Новые контакты дописываются строками.
  - Внешний коннектор: URL, POST JSON или GET с параметрами, секрет в заголовке `X-Baza-Secret`. Поля payload:
    phone, operator, region, supplier, supplier_label, source_phone, company, bought_at, lf_status.
  - У каждой: «Отправить тестовый лид» (79999999999, всё «тест»), выключить, удалить; счётчики отправлено / в очереди / не доставлено.
- Воркер `cab_deliver`: `cab_sync` после новых контактов кладёт их в `cab_outbox` по каждой включённой интеграции
  (только контакты, пришедшие после её подключения; повторы LF не отправляем), воркер раз в 10 с отправляет пачками
  (таблица — до 200 строк за запрос), при ошибке — повтор с растущей паузой, после 10 неудач строка «dead»,
  интеграция помечается «ошибка» с текстом.

- Bitrix24 (`services/bitrix.py`): входящий вебхук (права crm + user), «Проверить» тянет справочники —
  ответственные, стадии лидов, источники, воронки со стадиями. Создаём лид или сделку+контакт; контакт/лид ищем
  по номеру через `crm.duplicate.findbycomm` (переключатель «не создавать, если номер уже есть»); тип телефона,
  поле «Источник» (SOURCE_ID); в SOURCE_DESCRIPTION и COMMENTS — номер-источник, компания, поставщик, оператор, регион, дата.
- AmoCRM (`services/amocrm.py`): поддомен + долгосрочный токен, «Проверить» — аккаунт, воронки с этапами,
  пользователи. Контакт ищем `GET /contacts?query=<номер>`, нет — создаём (поле PHONE с enum), сделка на него
  с воронкой/этапом/ответственным/тегом (по умолчанию «ГЦК»), подробности — примечанием к сделке.
- Секреты (вебхук, токен, секрет коннектора) наружу не отдаются: форма показывает «задан», пустое поле при
  сохранении = оставить прежний.
- Telegram-бот клиентов (`workers/cab_notify.py`, `services/telegram_bot.py`): токен — ГЦК → «Токен Telegram-бота
  клиентов» (запасной `.env CAB_TELEGRAM_BOT_TOKEN`). Клиент в Настройках → Telegram жмёт «Подключить бота»
  (deep-link `t.me/<бот>?start=<код>`, код в `cab_clients.tg_connect_code`), бот привязывает чат к клиенту.
  Один чат — один клиент. Команды: /stats — сводка сейчас, /stop — отключить. Сводка ежедневно в 19:00 МСК
  (отметка `lg_settings tg_summary.<client_id>`): куплено сегодня (и повторов), за неделю и среднее в день
  (у молодого проекта — по дням его жизни), баланс в контактах и ₽, на сколько дней хватит, источников
  включено, статус закупки, топ-5 источников за день; предупреждение, если баланса меньше чем на два дня.
  Если бот заблокирован клиентом — чат отвязываем. Offset getUpdates — `lg_settings tg_cab_offset`.
- «Отправить тестовый лид» есть у всех четырёх интеграций; ответ показывает, что создано (например «создан лид #12»).

Не проверено на живых аккаунтах (у нас их нет): Bitrix24 и AmoCRM проверены только на ошибочных данных
(формат вебхука, 403/401, поддомен), Telegram — без токена. Первое подключение клиента смотреть по
`cab_integrations.last_error` и логу воркера `cab_deliver`.
